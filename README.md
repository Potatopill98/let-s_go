# 合作逃生3D Demo（Godot 4.7.2）v0.8

## 游戏概述
3D第一人称多人合作逃生游戏。玩家扮演从实验室被释放的实验体，在变异怪物的追击下逐层逃出设施。核心玩法是**单手持物 + 分工配合**：拿扳手的人负责修理、拿武器的人负责战斗、拿手电筒的人负责照明，一只手同一时间只能拿一个物品。所有美术资源均使用占位几何体，后续可替换。

## 操作说明
- **WASD**：移动
- **Shift**：奔跑
- **空格**：跳跃
- **Q**：闪避（快速位移）
- **左键**：攻击（空手挥拳 / 武器攻击，拿工具时不能攻击）
- **E**：交互（修理 / 拾取 / 搜索 / 刷卡 / 救援 / 开门）
- **G**：丢弃当前手持物品
- **R**：手枪换弹
- **F**：投掷背包中的投掷物
- **V**：放置背包中的放置物
- **1-4**：使用背包消耗品
- **ESC**：释放 / 锁定鼠标

## 手持物品系统（核心玩法）
- 玩家一只手同时只能拿**一个**物品
- **空手**：可以挥拳（低伤害 + 击退，1秒CD）
- **工具**（扳手 / 手电筒）：可以交互修理或照明，**不能攻击**
- **武器**（木棒 / 手枪）：可以攻击，**不能修东西**
- 拾取新物品时当前物品自动掉落在地，丢弃后可重新拾取
- 天然产生分工：有人修理、有人战斗、有人照明，需要相互配合

## 关卡流程

### 第一关「实验体收容区」
- 120×120米实验室收容区，初始暗红色灯光，氛围压抑
- 场景中寻找**扳手**（地上蓝色发光，捡起后熄灭）
- 维修**3个分散的发电机**：任意顺序均可，全部修好后统一通电、顶部主灯全部亮起
- 跟随**血迹指引**找到倒地的研究员尸体，按E搜索获得**门禁卡**（右侧显示持有提示）
- 大门通电后，拿门禁卡刷卡开门，进入第二关
- 牢房中的怪物：360度范围检测（墙壁可遮挡视线）、NavigationAgent3D自动寻路；警觉后头顶显示红色血条

### 第二关「狭长逃生走廊」
- **连接室**：明亮的缓冲房间，尽头是整通道金属大门，按E开启大门并启动测试
- 启动后**15秒倒计时**，随后紫色大型实验体（Boss）从连接室天花板破顶降下
- **主走廊**：约440米狭长通道，两侧成对分布19组侧门，红色警报灯三组相位循环闪烁（左亮 → 右亮 → 全黑），黑暗中仅靠灯光辨认环境
- 侧门外观完全一致，分为三类：锁死、可开（内有普通怪物）、可开（内有医疗包）
- **Boss**：可穿过所有障碍与门、速度为玩家奔跑的1.5倍、触碰造成致命伤害，持续追击
- 沿路开门推进，找到**最末组右侧的安全门**（绿色指示灯），按E开启（2秒后自动关闭）
- 进入**逃生走廊**：约50米狭长通道、绿色应急灯，Boss因边界限制无法进入
- 抵达**安全中间层**：16米明亮大房间，提示"已抵达安全区"，暂时安全

## 死亡与救援
- 血量归零后进入**倒地**状态：相机降低、只能缓慢爬行、无法攻击
- 倒地后持续流血（约100秒），怪物攻击会加速流失，倒计时结束则死亡出局
- 队友靠近倒地玩家按E可救起，救起后恢复部分血量

## 已完成模块
1. 玩家控制器：移动、奔跑、跳跃、闪避、挥拳、受击硬直、单手持物、倒地 / 救援状态机
2. 怪物AI：360度视野检测（墙遮挡）、NavigationAgent3D自动寻路、追击、攻击、受击击退、死亡
3. Boss系统：破顶释放、穿墙追击、致命触碰、边界限制
4. 手持物品系统：单手持物、工具 / 武器分类、自动 / 手动丢弃、丢弃后可重捡
5. 武器系统：木棒近战、手枪远程（实体子弹从枪口发射）、换弹、准心
6. 工具系统：扳手（修理发电机 / 门）、手电筒（照明）
7. 任务系统：发电机维修、研究员尸体搜索、门禁卡刷卡、滑动门交互
8. 门系统：双StaticBody可靠碰撞、门框 / 门板分离、侧面滑入开门动画
9. 警报灯系统：三相位闪烁、黑暗氛围、地面反光
10. UI系统：血量、手持物品、背包、交互提示、十字准心、怪物头顶血条
11. 广播公告系统：屏幕文字播报关卡目标与警告
12. 场景美化与程序化生成器：氛围灯、发光装饰、体积雾、辉光、随机布置

## 技术规范
- Godot 4.7.2 stable，GDScript
- 所有变量显式类型声明，禁止 `:=` 类型推断
- 禁止定义与 Godot 原生方法重名的函数
- 美术使用基础几何体占位，tscn / 脚本统一 UTF-8 无 BOM
- 门板碰撞加厚（0.6）防止高速穿透；碰撞直接挂在 CollisionObject 下保证可靠
- 子弹为独立实体，从枪口发射、飞出后与枪无关，连续碰撞检测防穿透
- 跨模块引用使用 const preload，避免全局 class_name 加载顺序问题
- 模块化开发，各功能独立可拆分
